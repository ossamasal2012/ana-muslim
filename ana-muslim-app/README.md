# تطبيق "أنا مسلم" — دليل الإعداد الكامل

تطبيق ديني شيعي أصيل: مواقيت صلاة محسوبة فلكياً (جعفري)، قرآن كريم خفيف بالرسم العثماني، سبحة إلكترونية، تقويم هجري بالمناسبات الشيعية، أذان تلقائي حتى مع إغلاق التطبيق، ونظام تحديث ذاتي عبر GitHub Releases.

## ⚠️ الخطوات الإلزامية قبل أول بناء (٣ خطوات فقط)

### 1) عدّل رابط المستودع في مكان واحد
افتح `app/build.gradle.kts` وابحث عن السطرين التاليين داخل `defaultConfig`:

```kotlin
buildConfigField("String", "UPDATE_VERSION_JSON_URL", "\"https://github.com/YOUR_GITHUB_USERNAME/ana-muslim-app/releases/latest/download/version.json\"")
buildConfigField("String", "GITHUB_REPO_RELEASES_URL", "\"https://github.com/YOUR_GITHUB_USERNAME/ana-muslim-app/releases/latest\"")
```

غيّر `YOUR_GITHUB_USERNAME/ana-muslim-app` إلى اسم المستخدم/المستودع الفعلي لديك على GitHub. هذا هو **المكان الوحيد** الذي يحتاج تعديلاً يدوياً في كل الكود.

### 2) أضف أسرار التوقيع (GitHub Secrets) — مرة واحدة فقط
تم توليد مفتاح توقيع حقيقي لك بالفعل (راجع مجلد `keystore-DO-NOT-COMMIT/` المُرسل معك). اذهب إلى: **صفحة المستودع على GitHub → Settings → Secrets and variables → Actions → New repository secret**، وأضف 4 أسرار بالضبط بهذه الأسماء:

| اسم السر (Secret Name) | القيمة |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | محتوى ملف `keystore-DO-NOT-COMMIT/keystore_base64.txt` كاملاً |
| `RELEASE_STORE_PASSWORD` | القيمة الموجودة في `keystore-DO-NOT-COMMIT/password.txt` |
| `RELEASE_KEY_PASSWORD` | **نفس القيمة تماماً** الموجودة في `password.txt` (كلمة السر واحدة لكليهما — راجع "ملاحظة تقنية" أدناه) |
| `RELEASE_KEY_ALIAS` | `anamuslim_release` |

⚠️ **لا ترفع أبداً** ملف `ana-muslim-release.keystore` أو `password.txt` إلى المستودع (ملف `.gitignore` معدّ مسبقاً لمنع ذلك تلقائياً). احتفظ بنسخة احتياطية من مجلد `keystore-DO-NOT-COMMIT/` كاملاً في مكان آمن خاص بك (تخزين سحابي شخصي مشفّر مثلاً) — **فقدان هذا الملف يعني عدم القدرة على نشر أي تحديث مستقبلي لنفس التطبيق أبداً**، لأن أندرويد يرفض تثبيت أي تحديث موقّع بمفتاح مختلف عن المثبَّت حالياً على أجهزة المستخدمين.

**ملاحظة تقنية**: أدوات التوقيع الحديثة (تنسيق PKCS12) لا تدعم كلمتي مرور مختلفتين لنفس الملف، لذا كلمة سر الخزنة وكلمة سر المفتاح هما نفس القيمة بالضبط — هذا طبيعي ومتوقّع وليس خطأً.

### 3) ادفع (Push) إلى الفرع main
بمجرد الدفع، يعمل `.github/workflows/release.yml` تلقائياً: يبني APK موقّعاً، يولّد `version.json`، وينشرهما كإصدار GitHub باسم `latest` (يستبدل القديم تلقائياً في كل مرة).

## كيف تُصدر تحديثاً جديداً لاحقاً (سطران فقط)
افتح ملف **`version.properties`** في جذر المشروع (**ليس** `build.gradle.kts`):
```
VERSION_CODE=2
VERSION_NAME=1.1
```
- `VERSION_CODE`: ارفعه رقماً واحداً بالضبط عن آخر مرة، دائماً يكبر ولا يتكرر أبداً.
- `VERSION_NAME`: غيّره لأي نص تريده يظهر للمستخدم.

احفظ (Commit) وادفع (Push) — كل شيء آخر تلقائي بالكامل، تماماً بنفس أسلوب مشروعكم السابق.

## لماذا لن تتكرر مشكلة "يظهر التحديث رغم أنه مثبَّت فعلاً"؟
هذه المشكلة الشائعة عولجت عمداً بثلاث طبقات حماية (راجع `data/update/UpdateRepository.kt` و`AnaMuslimApp.kt`):
1. المقارنة تتم دائماً مقابل `BuildConfig.VERSION_CODE` — رقم مُدمج داخل الـ APK نفسه وقت البناء، يعكس النسخة المثبَّتة *فعلياً* الآن، وليس أي رقم محفوظ قديم قد يصبح "باهتاً" (stale).
2. المقارنة أرقام صحيحة (Int)، لا نصوص، فلا يحدث خطأ نوع "9 أكبر من 10".
3. طلب `version.json` يُرسل دائماً بترويسات تمنع أي تخزين مؤقت (Cache)، فلا يُقرأ أبداً نسخة قديمة محفوظة من الملف.
4. عند نجاح التثبيت فعلياً، يُحذف ملف الـ APK القديم وكل أثر له تلقائياً من `AnaMuslimApp.onCreate()`.

## بنية المشروع (أهم المجلدات)
```
app/src/main/java/com/anamuslim/app/
├── data/prayertimes/   → محرك حساب مواقيت الصلاة الجعفري (بلا أي API)
├── data/quran/         → جلب/تخزين صفحات القرآن (Al Quran Cloud + تخزين محلي دائم)
├── data/tasbih/        → السبحة الإلكترونية
├── data/hijri/         → التقويم الهجري والمناسبات الشيعية
├── data/update/        → نظام التحديث الذاتي
├── alarm/              → جدولة وتشغيل الأذان (AlarmManager + Foreground Service)
├── notifications/      → قنوات الإشعارات
└── ui/                 → كل شاشات Jetpack Compose
```

## تنويه صادق حول حدود ما يمكن التحقق منه هنا
كل الكود كُتب ودُقّق بعناية فائقة، وتم اختبار محرك مواقيت الصلاة رقمياً فعلياً (وليس افتراضاً) بمقارنته بالكود المرجعي الأصلي. **لكن** بيئة التطوير هذه لا تملك Android SDK كاملاً لتشغيل بناء Gradle فعلي والتحقق من نجاحه 100% مسبقاً — البناء الحقيقي الأول يحدث على GitHub Actions (الذي يملك كل الأدوات اللازمة). إن ظهر أي خطأ بناء في تبويب Actions، انسخ نص الخطأ كاملاً وأرسله، وسيتم إصلاحه فوراً.
